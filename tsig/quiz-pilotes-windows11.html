Chapitre 1 · Fondamentaux

Introduction aux périphériques et aux pilotes

Objectifs : Définir · Expliquer l’OS · Identifier les enjeux

1.1 Qu’est-ce qu’un périphérique informatique ?

Un périphérique (ou appareil matériel) est tout composant matériel connecté à l’unité centrale (processeur et mémoire vive) via un bus interne (PCIe, SATA, M.2) ou un port externe (USB, HDMI, Ethernet, Bluetooth) permettant d’échanger des données avec le système informatique.

1.2 Qu’est-ce qu’un pilote (driver) ?

Selon la documentation officielle Microsoft Learn (What is a Driver?), un pilote (driver) est un composant logiciel permettant au système d’exploitation et à un périphérique matériel de communiquer entre eux. Il agit comme un traducteur / médiateur :

  • Il reçoit des requêtes génériques d’entrée/sortie (E/S ou I/O) provenant de l’OS ou des applications (ex. : « imprimer cette page », « lire le secteur X du SSD »).
  • Il traduit ces requêtes en instructions matérielles spécifiques compréhensibles par le contrôleur du périphérique (registres, signaux électriques, commandes de bus).
Pilotes logiciels (Software Drivers) : Certains pilotes ne sont associés à aucun matériel physique ; ils s’exécutent en mode noyau (fichiers .sys) pour accéder à des structures protégées du système (outils de monitoring, agents EDR/antivirus).

1.3 Rôle du système d’exploitation (Windows 11)

  • Abstraction : masque la diversité des composants matériels derrière des interfaces standardisées (API Win32, DirectX, etc.).
  • Partage et arbitrage : gère l’accès concurrent de plusieurs applications à un même périphérique (spouleur d’impression, file réseau).
  • Sécurité et stabilité : contrôle les privilèges d’accès afin qu’une application défaillante ne corrompe pas la mémoire ou les registres matériels.

Exercice corrigé 1.1 Abstraction

Énoncé : Un développeur crée un traitement de texte sous Windows 11. Doit-il écrire un code différent pour imprimer sur une HP LaserJet et sur une Canon Pixma ? Justifiez.

Corrigé : Non. L’application appelle les API standardisées de Windows (couche d’abstraction). Windows transmet la tâche au spouleur d’impression puis au pilote constructeur spécifique installé (HP ou Canon), qui traduit les commandes génériques en langage propre à l’imprimante.
Exercice corrigé 1.2 Pilote logiciel

Énoncé : Lors d’un audit Windows 11, vous repérez un fichier .sys appartenant à un outil de virtualisation ou d’EDR sans carte d’extension physique associée. S’agit-il d’une anomalie ?

Corrigé : Non. Il s’agit d’un pilote logiciel (software driver) s’exécutant en mode noyau pour accéder à des structures ou appels protégés de l’OS sans être lié à un périphérique matériel physique.

Architecture Windows · Driver Stack

Pile de pilotes & Couche HAL

La HAL (Hardware Abstraction Layer — hal.dll) isole le noyau des différences entre cartes mères, contrôleurs d’interruptions (APIC) et horloges. Au-dessus, une requête d’E/S (IRP — I/O Request Packet) traverse une pile verticale de pilotes :

Typologie des périphériques & Bus
  • Entrée : clavier, souris, scanner, webcam (USB HID / UVC).
  • Sortie : écran (DisplayPort/HDMI), imprimante, audio.
  • Stockage (E/S) : SSD NVMe (PCIe / M.2), disques SATA, clés USB.
  • Réseau : Ethernet RJ45, Wi-Fi / Bluetooth (M.2 / PCIe / USB).
  • Affichage : iGPU intégré ou dGPU sur port PCIe x16.
  • USB et hubs : contrôleurs hôtes xHCI (USB 3.x / USB4) gérant l’alimentation et l’énumération Plug and Play.

Exploration des ressources IRQ, MMIO et DMA

Exercice corrigé 2.1 · SSD NVMe & DMA

Énoncé : Pourquoi un SSD NVMe à 3 500 Mo/s ne peut-il pas fonctionner efficacement en Polling pur ? Quel mécanisme utilise-t-il principalement ?

Corrigé : En Polling, le CPU serait saturé à 100 % à attendre et copier chaque mot de donnée. Le SSD NVMe utilise le DMA pour transférer les blocs directement en RAM et les interruptions MSI-X pour notifier la fin des lots.
Exercice corrigé 2.2 · Filtrage sécurité USB

Énoncé : Un logiciel DLP bloque l’écriture sur les clés USB tout en autorisant la lecture. À quel niveau de la pile de pilotes s’insère-t-il ?

Corrigé : Il s’insère comme pilote de filtre (Upper ou Lower Filter) autour du pilote de fonction usbstor.sys pour intercepter et rejeter les IRP d’écriture sans réécrire le pilote complet.
Chapitre 3 · Architecture logicielle des pilotes

Modèles de pilotes : Ring 0 vs Ring 3, WDM, KMDF & UMDF

KMDF 1.33 · UMDF 2.33 · Signature WHQL
Mode Noyau · Ring 0

Accès matériel direct & Performance

Les pilotes partagent l’espace mémoire protégé du noyau Windows. Accès total au matériel, aux interruptions et au DMA. Risque critique : un bogue provoque un écran bleu (BSOD — Blue Screen of Death).

Mode Utilisateur · Ring 3

Isolation dans WUDFHost.exe

Le pilote s’exécute dans un processus isolé comme une application classique, via des API dédiées. Avantage majeur : si le pilote plante, seul son processus redémarre, sans faire planter Windows 11.

Origine & Certification

Inbox vs OEM & Signature WHQL

Les pilotes de classe (inbox) sont intégrés à Windows (usbstor.sys, hidclass.sys). Les pilotes OEM/IHV exploitent les fonctions avancées. En 64 bits, tout pilote noyau exige une signature numérique WHQL ou attestation Partner Center (.cat) garantissant authenticité et intégrité.

Critère WDM (Hérité) KMDF (WDF Noyau) UMDF (WDF Utilisateur)
Niveau d’exécution Mode Noyau (Ring 0) Mode Noyau (Ring 0) Mode Utilisateur (Ring 3 · WUDFHost.exe)
Stabilité système Risque élevé de BSOD Risque réduit (garde-fous WDF) Très élevée (isolation processus)
Accès IRQ / DMA Direct Direct Indirect (via couche noyau)
Complexité dev Élevée (PnP/alimentation manuels) Modérée (modèle objet WDF) Plus simple et débogage aisé
Version Windows 11 Maintenu pour compatibilité KMDF 1.33 UMDF 2.33

Exercice corrigé 3.1 · Choix KMDF vs UMDF

Énoncé : Un fabricant conçoit un lecteur d’empreintes USB et veut éviter tout BSOD chez ses clients Windows 11. Quel framework WDF privilégier ?

Corrigé : UMDF (User-Mode Driver Framework). Exécuté en Ring 3 dans WUDFHost.exe, un plantage du pilote redémarre uniquement son processus hôte sans générer de BSOD.
Exercice corrigé 3.2 · Altération d’un fichier .inf

Énoncé : Un technicien modifie manuellement une ligne dans le fichier .inf d’un pilote signé WHQL avant installation. Que fait Windows 11 x64 ?

Corrigé : La signature cryptographique est invalidée car l’empreinte du .inf modifié ne correspond plus au fichier catalogue .cat. Windows 11 bloque le chargement du pilote en mode noyau.
Chapitre 4 · Administration système Windows 11

Driver Store, VID/PID, HVCI et outils d’administration

DriverStore · PnPUtil · PowerShell · Secure Boot
Dépôt sécurisé

Le Driver Store

Tout package pilote doit d’abord être préchargé (staged) et validé dans C:\Windows\System32\DriverStore\FileRepository. C’est pourquoi une simple désinstallation réinstalle le pilote au redémarrage si le package reste dans le Driver Store.

Cycle de vie

Mise à jour, Roll Back & Purge

Windows Update : pilotes non critiques proposés dans Options avancées > Mises à jour facultatives. Roll Back : restaure la version précédente conservée dans le Driver Store. Suppression totale : cocher « Tenter de supprimer le pilote pour cet appareil » ou utiliser pnputil /delete-driver.

Sécurité Windows 11

Secure Boot & HVCI

Secure Boot (UEFI) bloque les bootkits dès le pré-démarrage. L’Intégrité de la mémoire (HVCI) dans Isolation du noyau vérifie les signatures en mode hyperviseur : un ancien pilote non compatible HVCI est bloqué.

Exercice corrigé 4.1 · Hardware ID PCIe

Énoncé : Un contrôleur réseau inconnu affiche PCI\VEN_8086&DEV_2725&SUBSYS_00248086. Comment trouver le pilote fiable sans utilitaire tiers douteux ?

Corrigé : VEN_8086 désigne Intel et DEV_2725 la carte Intel Wi-Fi 6E AX210. Télécharger le package officiel sur le site du constructeur du PC (Dell, HP, Lenovo) ou sur le portail Intel.
Exercice corrigé 4.2 · Réinstallation en boucle

Énoncé : Après désinstallation simple, le pilote audio oem24.inf se réinstalle à chaque redémarrage. Pourquoi et quelle commande exécuter ?

Corrigé : Le package reste stocké dans le Driver Store. Exécuter en Administrateur : pnputil /delete-driver oem24.inf /uninstall /force.

Inspection d’un .inf réel & simulation de défaut

Exercice corrigé 5.1 · Code 43 GPU

Énoncé : Après une coupure de courant, une carte graphique affiche un Code 43 et reste bloquée en 1024×768. Quelle démarche de diagnostic adopter ?

Corrigé : 1) Consulter eventvwr.msc et vérifier les câbles d’alimentation PCIe. 2) Purger le pilote du Driver Store et réinstaller la version constructeur. 3) Si le Code 43 persiste sur un autre poste sain, suspecter une panne matérielle (VRAM / GPU / étage d’alimentation).
Exercice corrigé 5.2 · Incompatibilité INF

Énoncé : Le fichier .inf téléchargé déclare PCI\VEN_10EC&DEV_8125 alors que le matériel réel affiche DEV_8168. Pourquoi l’assistant refuse-t-il l’installation ?

Corrigé : Le package cible une puce Realtek 2.5GbE (DEV_8125), tandis que la machine embarque une Realtek 1GbE (DEV_8168). Les Hardware IDs de la section [Models] ne correspondent pas.
Chapitre 6 · Cybersécurité & Gouvernance Parc

Sécurité des pilotes : BYOVD, DMA Protection & GPO d’entreprise

Ring 0 · IOMMU · Active Directory · WSUS / Intune
Menace critique · Ring 0

Attaques BYOVD

Bring Your Own Vulnerable Driver : un attaquant déploie un pilote légitime (signé) mais connu pour une faille mémoire, afin d’obtenir des privilèges noyau et désactiver les antivirus / EDR depuis Ring 0.

Protection matérielle

Kernel DMA Protection

Protège la RAM contre les lectures/écritures DMA physiques non autorisées via Thunderbolt ou PCIe externe, en s’appuyant sur l’IOMMU (Intel VT-d / AMD-Vi).

Déploiement & Sauvegarde

PnPUtil & DISM

Sauvegarde rapide avant migration : pnputil /export-driver * C:\BackupPilotes ou en ligne/hors ligne (image WIM) via dism /online /export-driver /destination:C:\BackupPilotes.

Active Directory · Stratégies de groupe (GPO)

Chemin de configuration : Configuration ordinateur > Modèles d’administration > Système > Installation de périphériques > Restrictions d’installation de périphériques

1. Bloquer les supports amovibles

« Empêcher l’installation de périphériques amovibles » : limite les risques de fuite de données et d’infection par clé USB inconnue.

2. Liste blanche par VID/PID

« Autoriser l’installation des périphériques correspondant à l’un de ces ID » : n’accepte que les références matérielles validées par la DSI.

3. Contrôle Windows Update

« Ne pas inclure les pilotes avec les mises à jour Windows » : centralisation et validation préalable via WSUS, Intune (WUfB) ou SCCM/MECM.

Exercice corrigé 6.1 · Liste blanche USB DSI

Énoncé : Bloquer toute clé USB personnelle tout en autorisant les clés chiffrées DSI (USB\VID_0951&PID_1666). Quelle stratégie GPO appliquer ?

Corrigé : 1) Activer « Autoriser l’installation des périphériques correspondant à l’un de ces ID » avec USB\VID_0951&PID_1666. 2) Activer « Empêcher l’installation de périphériques amovibles » (avec évaluation en couches). 3) Exécuter gpupdate /force.
Exercice corrigé 6.2 · Migration de 15 postes

Énoncé : Réinstaller Windows 11 sur 15 postes équipés d’une carte d’acquisition sans CD constructeur, mais fonctionnelle sur un poste témoin. Quelle procédure ?

Corrigé : Sur le poste témoin : pnputil /export-driver * D:\Pilotes_Poste. Sur chacun des 15 nouveaux postes : pnputil /add-driver "D:\Pilotes_Poste\*.inf" /subdirs /install.

Chapitre 7 · Consolidation des acquis

Synthèse générale, Glossaire & Bibliographie

14 Termes · 14 Références Microsoft Learn
Points clés à retenir pour l’examen BTS TSIG :
  • Un pilote est l’interprète entre Windows 11 et le matériel ; le modèle moderne est WDF (KMDF 1.33 / UMDF 2.33).
  • Les pilotes UMDF (Ring 3) isolent les plantages (pas de BSOD), tandis que KMDF (Ring 0) gère les débits critiques (GPU, réseau, stockage DMA).
  • Tout package pilote transite par le Driver Store (System32\DriverStore\FileRepository) et requiert une signature numérique valide.
  • L’identification par Hardware ID (VID/PID ou VEN/DEV), pnputil, driverquery et la résolution des codes 10, 28, 39, 43 forment le socle du support N2.
  • La gouvernance d’entreprise combine Secure Boot, HVCI, Kernel DMA Protection et restrictions par GPO / WSUS / Intune.
